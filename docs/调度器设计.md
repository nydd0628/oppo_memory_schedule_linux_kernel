# 压力感知的加权优先级物理页分配调度器
Pixel 7 / Android 16 / 6.1 内核设计草案 v1.0

## 一、设计目标和对外语义

在用户线程真正需要一张新物理页时，根据当前内存压力、申请者身份和等待历史，决定哪个线程先进入原生页分配器。内存充足时走现有路径；出现竞争时限制同时进入的请求数，把更多准入机会给 TOP，同时保障 FGS 取得服务机会。调度的单位是“一次 order-0 分配尝试”。系统不预扣空闲页，不把已属于后台的页转移给前台，也不改变回收、memcg 记账、OOM 或分配失败的原有语义。

期望收益是减少 TOP 在短时竞争中进入直接回收的机会，使其尾延迟更接近低压水平。若 TOP 单独运行也必须回收、后台已经开始回收、或压力主要来自未纳管的负载，调度器能发挥的作用有限。加权比例描述两类队列同时积压时的**准入次数**，不能当作物理页到账比例或完成时间保证。

## 二、放在内核的哪里

首版只管普通用户进程**私有匿名映射首次写入、确实需要一张新 order-0 页**的场景。malloc 尚未触页、只读共享零页、文件缺页、COW、换入、THP 和内核自身申请都不进入首版队列。如此可以准确解释“谁在申请哪一类页”，并避免回收线程自己被堵在等页队列中。面向顺序如下：

    用户首次写页 → 缺页路径确认身份和适用性
                  → 压力状态与资格检查
                      ├─ 直通 → 原生页分配
                      └─ 调度 → 类别 FIFO → 加权发许可 → 原线程执行原生页分配
                                                        ↓
                                    成功或失败均归还许可，再执行原缺页后续逻辑

本地参考 memory.c 的 do_anonymous_page 中，申请匿名实页的调用位于 PTE 安装之前；本地页分配参考代码有独立的 __alloc_pages_slowpath。首选在**已明确分配用途且尚未开始本次实页分配**的位置标记请求。若只在 direct reclaim 已经开始后才排队，就无法阻止这一轮争用。不要在全局 __alloc_pages 入口仅凭 current 的应用身份拦截所有调用，一个 TOP 线程也会代内核做其他用途的分配。

**等待点要与识别点分开审核。** 未持 PTE 自旋锁不等于可长期等待，缺页路径仍可能持有 mmap 读锁。实现首选沿目标分支已有的可重试缺页协议：确认允许重试后，释放协议要求释放的锁，失效旧 VMA 指针，再执行有界等待；重入时重新查 VMA、权限和 PTE，并消费一次性许可。不得在任意位置直接解锁后继续用旧 vmf，也不能只返回 RETRY 而每次重入都重新排队。许可绑定当前任务、mm、页对齐地址、故障类型和策略代次；重试发现页面已由别的线程安装、角色改变或任务退出，立即注销。若该分支无法证明锁与重试语义正确，该入口直通。参考文件不是已证明与运行镜像逐行一致的源码。

## 三、四个模块如何配合

| 模块 | 输入 | 输出与责任 |
|---|---|---|
| 身份分类 | 可信 Android 进程状态、角色版本号 | TOP、FGS、未纳管。由系统进程在角色切换时更新内核侧任务组标记，线程继承；内核快路径只读缓存。普通应用不能自报 TOP。 |
| 压力控制 | 该请求可使用的内存域水位余量、近期慢路径和扫描活动 | 发布档位、权重、许可上限和版本。PSI 用于识别已经发生的停顿和核对趋势。 |
| 准入仲裁 | 两类 FIFO、轮转游标、最老等待时间、可用许可 | 选择等待者，原子地把许可授予该线程；同一许可只授予一次。 |
| 生命周期与观测 | 分配返回、超时、取消、角色变化、关闭策略 | 归还或撤销许可，唤醒后继，区分正常授予、旁路和取消；全部路径可核对。 |

Android 的 FGS 是系统服务状态，单看 foreground cpuset 或 oom_score_adj 不足以唯一认定。用户切换应用时，可信分类器更新任务组角色和代次，触发等待项重新归类，保留原始到达时间。身份缺失或过期直接放行。首版保证的是 TOP 与 FGS **类别之间**的机会，各应用在同一类内按请求到达顺序竞争；一个多线程应用可能占据较多类内份额。若产品要求同类应用间也公平，可在类内增加按 UID 轮转，类别间算法不变。

## 四、怎样感知压力

首版只启用一个已核对资格的普通匿名内存域。用对应 eligible zone 的可用余量相对内核水位作主信号，考虑本请求不能使用的保留页、CMA 等约束；不把全机 MemAvailable 直接当作本次分配可取的页数。若实际 nodemask、迁移类型或域无法匹配，直接使用原分配器。一旦扩展多域，按节点和分配资格分开维护状态与队列，不让一处紧张拖住另一处。

| 状态 | 转换依据 | 动作 |
|---|---|---|
| 正常 | 余量充足且近期无持续下降 | 请求直通，无队列锁，无逐页 PSI 查询。 |
| 预警 | 余量低于进入线连续若干采样，或接近进入线并快速下降 | 开有限并行，TOP:FGS 初值 2:1。 |
| 紧张 | 余量进一步下降且慢路径或回收增多，或越过独立紧张线 | 缩小并行窗口，TOP:FGS 初值 3:1。 |
| 恢复 | 水位超过高于进入线的退出线并保持一段时间 | 先减弱偏置、增大并行度；稳定后解除排队并唤醒余下线程。 |
| 应急旁路 | 回收关键路径、系统进展异常、状态源失效或管理员关闭 | 停止新增等待，清退已有队列，保留 Linux 的内存保护机制。 |

阈值使用“距本域 low/high 水位的余量”，进入和退出取不同值，最短驻留时间抑制振荡。内核控制工作项周期刷新快照；分配快路径只读代次及档位。预警要在回收之前有机会启动，不能要求 PSI 已升高才允许排队。PSI 也不能单独续期，否则调度自身带来的等待可能污染控制信号。域水位与系统停顿的定义见 [Linux 物理内存文档](https://docs.kernel.org/mm/physical_memory.html) 和 [PSI 文档](https://docs.kernel.org/accounting/psi.html)。

## 五、加权优先级如何真正产生作用

**每域维护两条 FIFO 和 K 个并行许可。** 许可从授予起占用，到本次目标分配返回即释放；不跨页映射安装或业务处理。请求始终由原线程执行，以保留进程上下文、mempolicy 和内存记账。预警 K=4、紧张 K=2 可作原型初值；权重与 K 分别控制“谁先”和“同时多少”，均为待标定参数。

调度器在新请求入队、许可归还、角色变化或定时器到期时仲裁。每个空闲许可执行以下规则：

1. 若有达到老化线的队首，先选等待最久的队首；否则按档位的轮转表挑选。紧张档轮转表为 TOP、TOP、TOP、FGS，预警档为 TOP、FGS、TOP。使用持久游标，每授予一次前进一步；跳过空类，不积攒其历史信用。相同类取最早到达者。
2. 先在域锁内标记 GRANTED、占用许可、移出队列，再在锁外唤醒。新到达者也参加同一仲裁，不得绕过已排队的同类。某一类为空时另一类可用全部空闲许可，不预留空槽。两个许可若均在后台手中，新来的 TOP 要等至少一次归还；不抢占已经开始的分配。
3. 老化覆盖普通权重；下一次普通授予继续使用持久游标。持续饱和、无例外且请求均为一页时，四次普通授予中约三次 TOP、一次 FGS。单次慢分配可能长期占用一个许可，因此 3:1 不能代替墙钟等待保护。
4. 给每个等待项设两个时刻：老化线到达后提升下一次获许可的顺序；绝对期限到达仍未获许可则取消主动阻挡，走原生路径并记一次超时旁路。可从老化 1 ms、绝对等待 2 ms 开始评估。这两个值都不限制内核自身分配时长。旁路可能暂时使实际并发高于 K，故 K 是正常仲裁上限，不是所有物理页请求的硬上限。若短期大量超时，转应急旁路并记录原因，避免大规模同步唤醒反复出现。

**例子。** 假设两个许可原先都已占用，队列里已有 TOP 的 A1、A2、A3、A4 和 FGS 的 B1、B2；游标在紧张档第一格。前四次归还可依次授给 A1、A2、A3、B1。若 A 队列提前清空，B2 立即有资格取得空闲许可。若 B1 先触及老化线，下一次空位可提前给 B1。这里规定的是开始尝试的次序，A3 完全可能比 A2 先拿到页。

## 六、并发正确性和系统进展

- 每域有短时自旋锁保护队列、游标、inflight 和状态机；绝不在锁内睡眠、分配内存、调用原生分配器或访问用户空间。使用预分配的任务等待记录，禁止入队过程递归申请页。每任务最多有一个纳管请求，递归路径旁路。
- 请求状态为 NEW → WAITING → GRANTED → IN_ALLOC → DONE。等待者可转 CANCELLED 或 BYPASS。超时、信号、调度授予竞争时，在同一把锁下只有一个转换成功。已获许可但还没进入原分配器时若取消，需归还；已经开始则由统一返回路径归还。失败同样归还。定时器与等待记录生命周期同步，避免迟到唤醒使用已释放记录。
- K 调小时不撤回在途许可，只阻止新授予直到在途数降至新上限。关闭功能时先停止入队，唤醒等待者，允许在途请求自然归还；等引用清空后再回收队列。角色升级不截断进行中的分配。
- 只接受已审核、可睡眠且允许重试的普通用户缺页上下文。中断/原子上下文、持自旋锁、内核线程、回收/规整/写回任务、保留内存分配者、OOM 受害者及退出路径均旁路。纳管目标分配若进入直接回收，其递归申请不得再争同一许可。未纳管业务及系统紧急内存分配始终使用原机制。
- 即使线程可以睡眠，FGS 也可能持有 TOP 依赖的用户锁或同步 Binder 服务。权重无法推断这类依赖。已知优先级继承或同步服务关键线程可由可信来源标记旁路；未知依赖靠短等待、老化和故障解除限制。禁止对后台实行“等所有前台完成再放行”。
- 仅一次寄存器级身份检查也可能是热路径开销。功能关闭时用静态分支绕过；功能开启且正常档时不读取角色或加域锁（域适用性由轻量标记判断）。活动档计数按 CPU 汇总，逐请求跟踪默认关闭。

## 七、配置、可观测性与落地边界

配置面限定管理员：开关、适用域、各档进入/退出阈值、采样周期、权重、K、老化时限、绝对等待上限和队列容量。更新先验证权重均大于零、K≥1、老化线早于期限、退出线高于进入线；以版本化快照原子替换。过载时不追加等待记录，计数并旁路。绝不通过调高原生内核水位风险或关闭现有保护来达到策略目标。

每类导出入队、正常授予、老化授予、超时旁路、取消、分配成功/失败、等待分布和在途数。关键时间点是到达、授予、进入分配器和返回；共同记录 TID、角色代次、域、压力档及请求 ID。以“到达至返回”描述前台真实代价，同时看“下发至返回”区分排队与分配。后台最低服务用有积压时的完成速率和最长无进展间隔描述。指标计入超时、失败和未完成项，避免通过把等待移到分配器外制造好看的 p99。

建议代码边界：mm 内的策略核心维护压力快照、队列和许可；缺页入口适配层只做资格判定、锁释放/重试和结果清理；Android 身份适配层只发布可信角色。私有接口可采用 classify、admit_or_retry、consume_grant 和 finish 四类动作，统一兜住所有成功、失败和取消出口。第一版交付标准是能解释每次放行、关闭后恢复原行为、保留系统进展，且不承诺绕过实际缺页或回收成本。

## 八、已知事实与设计选择

Pixel 7 运行内核标识为 6.1.124-android14-11-g8769cc47188c。历史样本出现同线程分配与直接回收重叠，支持把减少前台回收暴露作为设计动机；尚未证明后台先取页造成这些延迟。本文选择的权重、并行度、等待上限和压力档位都是设计参数，未在运行内核实施。最重要的移植前置条件是拿到对应镜像的精确源码，核对匿名缺页的锁、重试、信号和内存域语义。
