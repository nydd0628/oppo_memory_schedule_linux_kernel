# Android 内存分配 QoS 自查与测试重点

**V3 · 2026-11-28 · 内核实现 `f3abdb17adf6` · Pixel 7（pantah）**

这份清单用于安排真机验证。最优先检查 **普通分配会不会因补池更慢、后台许可是否产生有用的约束，以及停机后页账是否归零**。另有两种补页恢复行为已经在 ARM64 QEMU 复现，可以先跑短用例确认。在真机上要核对 `uname -r` 和 `status` 中的 `pool_target`、`auto`、`refill_sources` 字段。工作区已有的 `out/pantah/memory-QoS-v2/boot.img` 对应 V2，V3 用例需要 V3 构建。[实现交接与构建命令](03-Android内存分配QoS实现交接.md)

## 1　两项已经复现的行为

均用 P 模式、driver 域，起始 8 页、会话上限 32 页、池内低线 4 页。开始时有充足的普通内存。使用 `test fail_after 0` 模拟普通补页连续失败，看到 `paused=1 pending=0` 后再用 `test fail_after -1` 恢复供给。两轮均无其他来源补池。

| 情况 | 测试步骤 | QEMU 实测 | 优化方向 |
|---|---|---|---|
| 补页供给恢复后仍保持暂停 | 前台用 `force` 取完 8 页，触发暂停。恢复供给后执行 `target 16`，观察状态，再执行 `recover`。 | 调整后 `target=16`、`F=0`、`paused=1`、`pressure_paused=0`。等待 300 ms 仍为空。执行 `recover` 后补到 16 页。 | 设一个有退避的恢复探测，或允许提大目标时在通过普通水位检查后重新探测。 |
| `recover` 清掉暂停后，扩容缺口还在 | 保留原来的 8 页，用 `target 16` 触发一次失败的扩容。恢复供给后执行 `recover`，随后再提交一次 `target 16`。 | 第一次 `recover` 后 `paused=0 pending=0`、`F=8`、目标 16 页。重发同一目标后才补满。 | 把未完成的扩容需求保留到恢复时。`recover` 可以区分补足刚要求的目标与常规池低线触发。 |

这里有两种状态。`paused=1` 是普通补页连续失败。`pressure_paused=1` 是 Zone 水位保护。把两者分开看，可以解释为何水位已恢复，池还长期缺页。平时若成功接到回收页，也会复位普通补页失败状态。本轮 QEMU 两个用例最终都通过停机对账。[补页触发](../mm/mem_alloc_qos.c#L293) · [补页失败](../mm/mem_alloc_qos.c#L846) · [恢复和手动目标](../mm/mem_alloc_qos.c#L1362)

## 2　真机优先检查

下面标为风险的项目有代码依据，实际影响需要用同条件对照裁决。每轮记下内核版本、角色 TGID、模式、启动及在线目标、自动调容状态、压力阶段、起止计数。先用固定目标跑完主对照，再开启自动调容。

### 2.1　直接回收能不能补池，以及谁承担回收代价

**代码依据。** 直接回收只有符合原始分配约束、Zone 水位通过且候选链里有足够相容页时，才会补池。每个同步回收候选链保留至少一张相容页给普通路径。内核会在剩余页进 PCP／buddy 之前准备池页，还可能在回收线程里直接执行多轮仲裁。每轮有批量上限，整个候选链处理和后续仲裁可重复。全局进度扣掉转入池的页，memcg 进度依据已经发生的解账。代码可以把普通路径的页留出来，但当前发起回收的线程仍需和其他请求竞争这些普通页。[回收入口及计数](../mm/vmscan.c#L2148) · [还普通页前的接收](../mm/page_alloc.c#L3694) · [批次扫描及仲裁](../mm/mem_alloc_qos.c#L739)

**怎么测。** 用真实文件缓存或前后台持续触页制造压力，先做同一 V3 的 N 与固定目标 W3。再用固定 32 页对比 V2 与 V3。版本对照会同时包含 V3 的容量管理改动，用来源计数和回收轨迹进一步归因。覆盖空池、普通水位在 MIN 附近、普通水位高于 LOW 后恢复三个阶段。单独观察 FGS 或未登记线程发起直接回收时的表现。

**怎么看。** 同步采集 `direct`、`kswapd`、`memcg`、`F/G/R`、Zone 水位、`pgscan_direct`、`pgsteal_direct`、`allocstall_*` 以及 `mm_vmscan_direct_reclaim_begin/end`。联合查看 TOP/FGS 请求端到端 P99/P99.9、普通回收变长的请求和 OOM/LMK。短 trace 窗口可把回收事件、`mem_qos_pool` 和 `mm_page_free_batched` 对到同一 TID，估计本线程从接收池页到首个可见普通释放事件的间隔。

- 自然回收有活动，池有缺口，`direct=0` 时先对齐暂停状态、候选条件与池容量。当前计数只记录成功接收，无法单靠零值区分具体拦截原因。QEMU 受控触发的全局直接回收曾补回 8 页，自然压力轮观察到的补池来自 `kswapd` 和 memcg。
- 如果 TOP 略快但原生直接回收、普通分配长尾或 OOM 明显增加，优先考虑让普通页的释放早于授权唤醒，限制一次同步回收可接收的页数和 CPU 时间。也可以增加按来源和原因统计的候选、保留、拒收计数，帮助定位自然命中不足。

### 2.2　后台许可是否只是多了一次等待

**代码依据。** F/W 下，相容 FGS 在首次原生取页前进队。领到许可后马上消费，随后的原生分配阶段当前没有独立的在途上限。池空时后台可以连续获得单边许可，队满或超时可以旁路。3∶1 只约束两类同时可服务时的授权顺序。允许睡眠的匿名缺页调用仍处于原生 mmap/VMA 锁保护下，等待时间可能增加同进程 `mmap`、`munmap`、`mprotect` 等操作的延迟。[资格消费](../mm/mem_alloc_qos.c#L515) · [后台原生分配](../mm/page_alloc.c#L5877) · [匿名缺页入口](../mm/memory.c#L4267)

**怎么测。** 分别用低压力 FGS 单边高并发、双方持续争用和前台池空三类负载。P 与 W3 使用相同池，观察加入队列之后的差异。W1 与 W3 保持同样参数，仅改变权重。可以在受控负载的同一进程增加一个做 map/unmap 的线程，测它的耗时。

**怎么看。** 比较 FGS `permitted_ok/fail`、`fgs_bypass_ok/fail`、分原因旁路、FGS 完成率，以及 TOP P99/P99.9 和总吞吐。取诊断 trace 时用 `claim_permit` 到同请求 `return` 重建原生分配在途量，再按时间窗看是否集中放行或一起超时回退。只对 `detail=1` 的授权按序号校验 WRR，实际成功率单独计算。如果低压力已出现明显开销，或压力下许多后台请求仍同时进入原生分配，可对照试验按压力启动后台门控、限制原生在途量，或合并到期旁路的唤醒。

### 2.3　低水位是否早于普通分配的明显退化

**代码依据。** 水位检查用 `ZONE_NORMAL` 的页统计和原生储备扣减。回收批次在普通页释放之前检查当前水位，待释放的候选页尚未进入普通空闲链。某一整批原样送回原生路径后，下一次才能观察更新的水位，PCP 批量归还也会影响统计时序。主动补页在批次开始前检查 `HIGH + 批量`，随后在锁外做原生分配，发布时再检查目标和页属性。压力变化很快时，预检结果是当时的快照。启动预填允许原生普通分配尝试，运行时才有 QoS 的 HIGH 预检。临界压力冻结自动目标，空闲池页继续占物理内存。[接收条件](../mm/mem_alloc_qos.c#L739) · [普通补页预检](../mm/mem_alloc_qos.c#L809) · [Zone 水位](../mm/page_alloc.c#L4316)

**怎么测。** 固定相同压力轨迹依次用 32、128、256 页，1024 页留作后续边界档。固定目标先测，另跑自动调容。分别测试在高水位启动、压力已到但仍能启动、压力跨 MIN/LOW/HIGH 再回升。对 `pressure_paused` 和 `auto frozen` 分别画时间线。

**怎么看。** 同时看 `F/G/R/retiring`、真实 `Normal` Zone 水位、PSI、直接回收、OOM/LMK、启停耗时和前后台交付。重点看大池库存长期占着时是否同步出现普通分配失败，或者启动大池后普通水位快速下降。若观察到启动退化，可试用运行时同等级的预检或按水位逐步启动。若回收批次初始水位略低而反复错过补池，可试先释放满足保护线所需的普通页，再对剩余候选复查。两种策略单独做对照。

### 2.4　启停、缩容和角色切换能不能收干净

**代码依据。** 停机撤下会话入口，取消定时和补页工作、撤销还未领取的授权，然后等待 SRCU 内在途调用。一些已获许可或正在回退的请求还会继续原生分配。`stop` 与 `status` 共用控制锁，停机未结束时状态读取也可能等待。缩容先还空闲页，仍有已授权或已预留的页时允许暂时超过新目标。会话按进程对象登记角色，应用进程重启后需重新登记。[停机及对账](../mm/mem_alloc_qos.c#L1094) · [会话身份](../mm/mem_alloc_qos.c#L161)

**怎么测。** 在池空、刚授权、后台原生慢路径、回收补页在途等时点做 stop/start。循环扩大和缩小目标，包含缩到比 G 更小。另测 A/B 进程退出后重启，确认下一轮登记和计数对应新进程。记录 `stop` 的实际耗时和内核日志。

**怎么看。** 终止后要求 `F=G=R=retiring=0`、`live=0`、`permits_pending=0`、`balanced=1`。池占用应始终受会话 MAX 约束。缩容应在已授权页和在途工作退出后收敛。grant、claim、revoke 里同一物理页持有期的编号不能重复交给两个请求。FGS 的池页 `claimed` 应为零。遇到停机长等待时同时看 trace 或任务栈，避免只依靠可能在等锁的 `status` 判断。

### 2.5　持池页对规整、隔离和高阶分配的影响

**代码依据。** 池页通过正常页准备持有引用，空闲池页只挂在自己的链表上。接收会筛掉隔离页块，领取时也查页属性。已在池里的空闲页当前缺少主动对接隔离或下线的释放钩子。正常的隔离扫描可能把仍有引用且既不在 LRU 又未标记可迁移的页视作不可移动。这是风险推断，是否影响手机取决于实际页布局和用到的隔离路径。[池页持有](../mm/mem_alloc_qos.c#L710) · [回收候选筛选](../mm/page_alloc.c#L2633) · [原生页隔离](../mm/page_isolation.c#L130)

**怎么测。** 普通真机压力轮记录大池和关闭会话时的 `/proc/buddyinfo`、`compact_stall`、`compact_fail` 和高阶分配失败。若有可控的 ARM64 虚机或专门的隔离环境，用停止会话前后的同一区间作对照，观察页块隔离返回、耗时和停机后是否恢复。常规实验可以先检查高阶分配与规整指标。

**怎么看。** 同样压力下高阶失败反复出现、关闭会话后消失时，再检查是否和池页所在页块重叠。若重合成立，可考虑加入隔离前按范围退页并阻止新接收，或从页源上避开相应区域。

## 3　自动调容和计时的改进点

| 项目 | 当前实现容易漏什么 | 怎么验证或比较 |
|---|---|---|
| 250 ms 采样和约 1 s 空闲缩容 | 空池信号主要来自新 TOP 尝试时池为空，或采样时仍有空池排队。请求入队时还有页，之后短暂缺页并在下一次采样前超时，可能未触发扩容。接近 1 s 的间歇负载也可能反复扩缩。 | 用小池跑多个短突发，分别改变间隔。比较同初始目标的固定模式和 auto。保留每个 `auto_grow/auto_shrink`、`trim`、实际 F 以及 TOP 超时。若漏报，考虑累计真正等待池页的时长和空池超时，增加最小驻留时间。 |
| 水位拒绝时的补页唤醒 | 水位拒绝在分配前发生，无需增加连续失败计数。已经启动的补页工作可能一直按配置退避重新检查。默认例子是 1000 μs。 | 在缺页且普通内存持续低于 HIGH 时，量工作队列唤醒、补页线程 CPU 和回到可补水位所需时间。若多数唤醒没有产出，可让水位拒绝使用更慢的退避或回收事件触发。 |
| 250 μs 预算与实际加成 | 计时从入队开始，限制的是提交授权的截止时间。唤醒调度、线程继续仲裁和原生回退可让实际延迟更长。250 μs 也不能直接与应用首次触页等同。 | 比较 enqueue→grant、grant→claim 及 enter→return。超时单列，再看应用端首次触页。高负载时比较 `sched_switch` 和 QoS 事件，分辨仲裁、唤醒和回退各自的贡献。 |
| PSI 与内核成功口径 | QoS 自身排队没有显式走原生直接回收的 PSI memstall 记账；`return` 记录分配结果，后面还有 memcg 计费和页表安装。 | 用应用完成率和首次触页延迟交叉核对。即使 PSI、`allocstall` 降低，也同时验证 QoS 排队有没有变长。启用 `TRACE=2` 的详细轨迹与轻量采集轮分开做。 |

源码入口可查 [空池观察及排队预算](../mm/mem_alloc_qos.c#L625)、[自动调容采样](../mm/mem_alloc_qos.c#L911)、[补页重试](../mm/mem_alloc_qos.c#L872) 和 [匿名页计费](../mm/memory.c#L4285)。

## 4　实际先跑这几组

| 顺序 | 要跑的对照 | 要保留的证据 |
|---|---|---|
| 1 | 确认 V3 构建，先跑功能自测、补页恢复和高压力下停机。 | 每轮启动与停机 `status`、失败原因、页账、内核告警、stop 耗时。 |
| 2 | 同一 V3 固定小池，交错运行 N、P、W1、W3。先轻压力，再用覆盖自然缺页和回收的压力。 | TOP/FGS 独立的成功/失败/旁路、端到端 P99/P99.9、完成率、总吞吐、Zone 水位和各来源实际补页。 |
| 3 | 固定相同小池的 V2 与 V3，关闭 auto，观察接入同步回收后的表现。 | `direct/memcg`、回收进度与耗时、普通分配长尾、高阶失败或 OOM/LMK。按有无自然命中分开记。 |
| 4 | V3 固定 32、128、256 页，再用相同起始目标做 auto 对照。 | 真实 F 与目标曲线、空池时长、扩缩次数、归还及普通补页成本。先用数据选有收益的最小目标，再测试 1024 页边界。 |

测试端用具备读取权限的 shell 保存基线和结束快照，详细时间线用单独的诊断轮采集。

```sh
uname -r
cat /sys/kernel/debug/mem_alloc_qos/status
cat /proc/zoneinfo
cat /proc/pressure/memory
grep -E '^(pgscan_|pgsteal_|allocstall_|oom_kill|compact_)' /proc/vmstat
```

主指标用同一负载下的 TOP 端到端尾延迟，并列 FGS 完成率、总吞吐、分配失败和回收开销。以多轮对照和应用完成结果裁决性能。对于页归属错误、停机后计数未归零、持续回收不前进或新增 OOM/LMK，先单独保留该轮的状态和日志，优先检查正确性。
