# 匿名页准入调度器的内核接口

`CONFIG_ANON_PAGE_ADMISSION` 在满足依赖的 ARM64 单节点内核上默认编入。启动后保持关闭。只有普通用户私有匿名映射的写缺页可以获得许可，已有 PTE、COW、换入、THP、userfaultfd、回收及保留内存上下文均沿原路径处理。

## 管理接口

接口位于 `/proc/sys/vm/anon_page_admission/`。写入配置、发布角色和读取统计需要相应文件权限及初始用户命名空间的 `CAP_SYS_ADMIN`。

| 文件 | 用途 |
|---|---|
| `enabled` | 写 `1` 启用，写 `0` 停止新等待并唤醒等待者。已经进入分配器的线程自然结束。 |
| `experiment_uids` | 启用 CPUSETS 的内核提供。一次写入 A、B 的两个不同非零十进制 Android UID（含用户编号），切换到双 APK 分类。读回当前 UID 对。默认值 `0 0` 使用原有 pidfd 角色接口。 |
| `role` | 写入 `pidfd role lease_ms`。文件描述符在写入进程内用 `pidfd_open(tgid, 0)` 获取。角色 `1` 为 TOP，`2` 为 FGS。租期为 1–60000 ms。写入 `pidfd 0 0` 撤销分类或让该任务组旁路。 |
| `policy` | 读取或写入下表顺序的整数向量。写入时先验证整组配置，再发布。 |
| `stats` | 查看单节点水位余量、压力档、当前权重、许可和分角色计数。 |

pidfd 模式的角色按任务组共享。发布者可在角色不变时续期。租约过期即恢复直通，新的进程组需要独立标记。Android 系统服务可用同一接口随应用状态变化更新角色。此内核接口也支持由有权限的测试进程手动标记，方便在接入 Android 的自动发布者之前验证调度。

## Pixel 7 双 APK 实验

脚本每轮从本次安装的两个 APK 获取完整 UID，确认它们各自独占 UID。每个负载工作线程都使用实际 PID、TID 核对；同一应用内其他符合条件的线程也可能被计数。需要区分工作线程贡献时按 TID 过滤 trace。

| 应用 | 脚本核实的 Android UID 状态 | 内核在发起缺页的线程上匹配 | 准入类别 |
|---|---|---|---|
| A | `2 (TOP)` | A 的 UID 且 cpuset 恰为 `/top-app` | TOP |
| B | `4 (FOREGROUND_SERVICE)` | B 的 UID 且 cpuset 恰为 `/foreground` | FGS |

1. 启动两个负载，暂停在测量起点。脚本用 `cmd activity get-uid-state "$uid"` 检查 UID 状态，用下面的命令检查每个工作线程。按脚本的稳定窗口重复核对；缺失、读取失败和启动过渡期都继续等待，超时则跳过本轮。
2. 条件稳定后，在有权限的设备 shell 中运行下面的配置命令。对照轮保持 `enabled=0`；策略轮开启后记录起始 `stats`，再同时放行两个负载。两种轮次使用相同的角色检查。
3. 测量期间定期及结束时复核两列条件和工作线程身份。发现变化、线程意外退出或查询失败，记录时间及原因，整轮作废。轮询只能检出采样时可见的变化。内核在每个新请求、队首授予和缺页重试时检查线程分组；此模式忽略 pidfd 角色，条件失配直接旁路，已经进入分配器的分配自然结束。
4. 先采集结束 `stats`，按起止差值分析。正常结束、中止和超时均先关闭策略，再清除 UID 对；下轮重新核实、配置。UID 对持续有效直至重配或清除。

```sh
# 设备侧，每个实际工作线程分别执行。应得到唯一的预期绝对路径。
awk -F: '$2 ~ /(^|,)cpuset(,|$)/ {print $3}' "/proc/$pid/task/$tid/cgroup"

# 设备侧，uid_a、uid_b 取自本轮。写入失败则中止本轮。
ctl=/proc/sys/vm/anon_page_admission
echo "$uid_a $uid_b" > "$ctl/experiment_uids" || exit 1
cat "$ctl/experiment_uids"
echo 1 > "$ctl/enabled" || exit 1
# ……开始测量，保存起止统计并检查角色……
echo 0 > "$ctl/enabled"
echo '0 0' > "$ctl/experiment_uids"
```

## 压力与调度参数

| 顺序 | 配置 | 默认值 |
|---|---|---|
| 1–3 | 预警余量、紧张余量、恢复余量，单位为页 | 1024、256、2048 |
| 4–5 | 采样周期、驻留时间，单位为 ms | 20、60 |
| 6–9 | 预警 TOP、预警 FGS、紧张 TOP、紧张 FGS 权重 | 2、1、3、1 |
| 10–11 | 预警、紧张并行许可数 | 4、2 |
| 12–13 | 老化、等待截止时间，单位为 μs | 1000、2000 |
| 14–15 | 排队容量、单采样周期内触发应急旁路的超时次数 | 128、8 |

节点 0 是首版唯一的域。控制器从该分配可用的 zonelist 读取水位，以可用区中的最大余量判断是否尚有可用回退区。实际的 GFP/CMA 资格与该域不匹配时，缺页直通。压力档 `0` 到 `4` 依次为正常、预警、紧张、恢复、应急旁路。恢复使用 1:1 权重和比预警多两个的许可额度，许可总量上限为 64。

## 观测

`stats` 提供排队、授予、老化授予、超时旁路、取消、其他旁路、进入分配器、分配成功和失败的累计计数。延迟直方图按 `<250`、`250–499`、`500–999`、`1000–1999`、`≥2000` μs 分桶。排队时间从入队计至获准或旁路。分配时间从进入原生分配器计至返回。总时间是入队至返回，包含已入队后超时旁路的分配。系统停顿另由 PSI 提供，未完成请求用在途和活动记录数观察。

逐请求事件在 tracefs 中默认关闭。开启 `events/anon_page_admission/anon_page_admission` 后，可按请求 ID 对齐到达、授予、进入及返回事件。角色变更可能使入队与授予属于不同类别，可用同一请求 ID 对齐。事件 `0–8` 的顺序与 `stats` 的事件列一致。
